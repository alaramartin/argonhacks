1️⃣ Your Goal: Hackathon Problem Statements
You'll build in at least one of the hackathon's problem statements.

Problem Statement One: Million Token Engineering

Gemini 4 Argon is SOTA on codebase understanding, which measures long-horizon software engineering. With up to 1M continuous output tokens in a single response, Argon makes it possible to build systems that work across hundreds of files, keep interfaces consistent as they change, and grind tedious tasks where other models’ accuracy drops off. The work teams put off for years (legacy migrations, language translations, framework upgrades) is exactly where that scale matters. Pick something that has before seemed as a monumental task, do it, and measure your improvement over a baseline.

Problem Statement Two: More Dimensions

Gemini 4 Argon is also SOTA on long video understanding, and its output window lets it generate high-fidelity 3D games and procedural worlds in a single pass. A single pass is only the first draft. Build a system that renders what it made, watches the result, critiques it against the goal, and fixes it in a loop.

8️⃣ Judging Process
Judging will take place in two rounds.

Round One: Hackers will be assigned to judging groups in different rooms of the venue. Each team will have ~3 minutes to live demo their project, followed by 1-2 minutes of Q&A. The following criteria will be used:

Working live demo (50%): Does the application run live with real inputs during judging? Did the team use Gemini 4 Argon (gemini-4-argon), Managed Agents or companion models effectively, with a real verification loop?

Problem and usefulness (25%): Does it solve a concrete problem for a specific person in one of the hackathon tracks? Could this grow into a product or open-source tool people use after today?

Originality ("never built before") (15%): Is this project only possible because of Gemini 4 Argon's 1M unified context, long decode, frontier reasoning or multimodal orchestration?

Clarity of pitch (10%): Did the team show who the user is and demonstrate the working product clearly in 3 minutes without slides?

Round Two: The top six teams demoing on stage in front of a panel of judges and all attendees. Each team will have ~3 minutes to live demo their project, followed by 1-2 minutes of Q&A. The same criteria as above will be used, though with equal weighting for each category.

Get started in 15 minutes

1. Claim your pre-provisioned account from the Google team at kickoff
2. Install the official Gemini API skills in your coding agent so it writes current gemini-4-argon and Interactions API code, or prototype directly in Google AI Studio Build and Google Antigravity.
3. Run your first gemini-4-argon call on the Interactions API using google-genai or @google/genai version 2.3.0 or later.
4. Reach out to the Google mentors onsite whenever you hit a blocker.
   Give your coding agent the Gemini API skills
   Coding agents trained on older data often suggest deprecated SDKs or removed parameters. Install the official skills so your agent knows gemini-4-argon, the Interactions API and Managed Agents:
   Shell
   npx skills add google-gemini/gemini-skills --skill gemini-api-dev npx skills add google-gemini/gemini-skills --skill gemini-live-api-dev agy plugin install https://github.com/google-gemini/gemini-skills
   What to know when calling Gemini 4 Argon
   The Interactions API is the recommended endpoint for new projects. One API covers both models and managed agents, supports server-side state (previous_interaction_id) and handles background execution.
5. Control reasoning depth with thinking_level
   Gemini 4 Argon uses thinking_level ("low" | "medium" | "high") to control how much reasoning effort the model spends before responding:

- "medium" (default): balances speed, cost and first-pass accuracy for interactive coding and agentic tool use
- "high": maximizes reasoning depth for multi-file debugging, security vulnerability patching, formal maths and upfront system design
- "low": minimizes latency and cost for fast classification, routing and targeted extraction
  Python
  from google import genai
  client = genai.Client()
  interaction = client.interactions.create(
  model="gemini-4-argon",
  input="Build a single-file HTML drum machine and synth using the Web Audio API with a 16-step sequencer, tempo slider, and a live waveform visualizer.", generation_config={
  "thinking_level": "medium" # "low" | "medium" (default) | "high" },
  )
  print(interaction.output_text)

2. Shared 1M-token context window and long decode (background=True)
   Earlier models capped total output (thinking plus response) at 64K tokens. In Gemini 4 Argon, input, thinking and output share a single 1M-token window:

- default output limit is 65,536 (64K) tokens on the Interactions API for both streaming and non-streaming calls with no code changes needed
- to generate past 65,536 tokens (up to 1M tokens minus your input), set background=True and set max_output_tokens above 65536 on the Interactions API
  Set max_output_tokens high enough that deep thinking does not cut off your multi-file diff or proof mid-output, and low enough to cap spend on open-ended prompts:
  Python
  import time
  from google import genai
  client = genai.Client()
  interaction = client.interactions.create(
  model="gemini-4-argon",
  input="Write a complete multi-module physics simulation and test suite.", background=True,
  generation_config={
  "max_output_tokens": 262144,
  "thinking_level": "high",
  },
  )
  while interaction.status in ("in_progress", "queued"):
  time.sleep(5)
  interaction = client.interactions.get(id=interaction.id)
  print(interaction.output_text)

3. Clean up legacy parameters
   If you are adapting code written for Gemini 2.5 or Gemini 3 models, remove these deprecated settings when calling gemini-4-argon:

- replace thinking_budget with thinking_level (thinking_budget is deprecated and returns a warning)
- remove temperature, top_p and top_k (custom sampling values are ignored by gemini-4-argon and return a deprecation warning)
- remove explicit cached_content calls (implicit context caching runs automatically at a 95% discount on cached input tokens; introductory pricing through 30 November 2026 is $2 per 1M input tokens and $10 per 1M output tokens)
- increase HTTP client timeouts to 15 to 20 minutes for complex "high" thinking prompts, or run them asynchronously with background=True

4. Run Gemini 4 Argon inside Managed Agents
   You can pass "model": "gemini-4-argon" to the Antigravity managed agent (antigravity-preview-09-2026). Google provisions a hosted sandbox where Argon plans, writes code, verifies its own output, searches the web and calls MCP tools in a single API call:
   Python
   from google import genai
   client = genai.Client()
   interaction = client.interactions.create(
   agent="antigravity-preview-09-2026",
   agent_config={
   "type": "antigravity",
   "model": "gemini-4-argon",
   },
   input=(
   "Audit https://web.dev for performance, Core Web Vitals, and SEO. " "Query Google's PageSpeed Insights API for both Mobile and Desktop strategies. "
   "Check search indexing with Google Search for site:web.dev. " "Format the output as a side-by-side scorecard table with prioritized fixes."
   ),
   environment="remote",
   )
   print(interaction.output_text)
   When your agent needs API tokens (such as GitHub or Stripe), register them with the Credentials API (client.credentials.create) and restrict the sandbox network allowlist (environment={"type": "remote", "network": {"allowlist": [...]}}) so secrets are injected at the proxy and never enter the model context.
   5 patterns that save hours in a 1-day hackathon
1. Align on intent before long runs. Share your goal with Argon and ask it to surface clarifying questions, edge cases and architecture trade-offs before writing code. Once you agree on the plan and confirm it can reach your tools and docs, step back and let Argon execute the multi-file build to completion instead of prompting turn by turn.
1. Give Argon a verification loop. Argon performs best when it can test its own changes against a concrete pass or fail signal. Point it at your test suite, compiler output or runtime logs, or ask it to write a headless Chrome verification script first, record a
   baseline score, and iterate in a loop until every check passes with zero regressions. 3. Use multimodal references and agentic video understanding. Pass 1 or 2 reference images when building frontends or 3D scenes (Blender, Three.js, WebGPU), or ask
   Argon to extract typography, color palette and layout rules into a DESIGN.md file first. When debugging UI or timing bugs, record a short screen-share talking through the issue alongside your console logs; Argon's agentic video understanding scrubs across timestamps, inspects high-resolution frames and patches the underlying components.
1. Orchestrate Argon with Flash and media subagents. Use gemini-4-argon (thinking_level="medium" or "high") as the lead architect to decompose the problem, define interfaces and review diffs, while delegating parallel leaf modules and high-frequency checks to gemini-3.8-flash subagents. Let Argon call gemini-nano-banana-2.1 for UI textures and sprites, gemini-3.8-live for real-time voice interaction, and gemini-3.8-flash-tts or lyria-3.5 for voice and music.
1. Capture codebase quirks and visual explainers. When Argon solves a non-obvious setup or build quirk, ask it to write the lesson into AGENTS.md or a reusable skill so your team never hits the same snag twice. Before your final demo, ask Argon to generate an interactive HTML architecture diagram or pipeline walkthrough of what you built.
